## 1. Замысел и границы вывода

Требования к работе задаёт AGENTS.md. Этот документ отделяет их от того,
что фактически проверяет существующий код. Код 0 означает техническую
готовность к содержательной проверке в пределах реализованных условий.
Научная достоверность, полнота обзора и приёмка человеком из этого кода
не следуют. Название full в scripts/run_verifier.py обозначает проверку
графа и не включает сверку научных утверждений.

Цель полного покрытия графа — заметка для каждого индикатора. Фактический
минимум check_graph.py — пять заметок; это разные условия.

## 2. Постановка

- Проверяемые материалы: paper/indicators_table.md, обзор в Markdown и LaTeX,
  локальные источники и заметки notes/.
- Таблица содержит 25 строк и шесть столбцов. Новая научная оценка строк
  в этапе согласования документации не выполняется.
- Измеряем: нарушения реализованных условий; отдельно регистрируем требования,
  для которых пока нет автоматической проверки.
- Для воспроизведения записывать коммит, локальные изменения, команду,
  версию Python, дату и код завершения. Старый успешный журнал не является
  результатом проверки текущего состояния.

## 3. Договор и фактическая проверка

Нормативная шкала sensitivity — high / medium / low. Нормативные категории —
chemical, physical, biological, labile carbon. Отступления текущих проверок
от договора показаны явно, без изменения кода checks/.

| Требование | Реализованная проверка | Ограничение |
|---|---|---|
| Ровно шесть столбцов в заданном порядке | test_properties.py::load_rows и check_graph.py::read_indicators сравнивают заголовок целиком | check.py проверяет лишь наличие обязательных столбцов |
| Минимум 10 строк | check.py::check_table | Число строк не доказывает полноту набора индикаторов |
| category из четырёх нормативных групп | test_every_category_has_row требует ровно набор этих групп | check.py дополнительно допускает microbial |
| sensitivity из high / medium / low | test_sensitivity_whitelist и check.py проверяют список допустимых значений | Оба пока допускают также medium-high; нормативная шкала не обеспечена полностью |
| indicator уникален | check.py и test_indicator_unique | Синонимы и разные сокращения одного индикатора не распознаются |
| indicator и method без заглушек | check.py::is_placeholder | Проверяется ограниченный список маркеров, а не научный смысл |
| Источник существует, расширение PDF/MD/TXT | check.py; test_every_source_file_exists проверяет существование | Выход пути за paper/ и научная релевантность не проверяются |
| source_page указывает реальную физическую страницу PDF с нумерацией от 1 | check.py проверяет целое число 1..999 | Длина PDF, цитата и соответствие страницы не проверяются |
| Для MD/TXT указан раздел или диапазон строк | check.py проверяет только отсутствие заглушки в source_page | Поиск цитаты по указателю не реализован |
| Строки отсортированы high → medium → low, внутри группы по indicator.casefold() | Автоматической проверки нет | Текущая таблица не отсортирована; medium-high требует отдельного решения |
| Каждый индикатор имеет заметку, группу и источник | check_graph.py сопоставляет короткие коды/названия и требует минимум пять заметок | Полное покрытие и ограничения онтологии не проверяются |
| Источник связан с существующей заметкой запроса | check_graph.py ищет строку найденЗапросом в тексте | Существование цели, тип связи и содержание не проверяются |
| Markdown и LaTeX содержат одинаковые источники и согласованный текст | test_md_and_tex_literature_match сравнивает количество позиций | Состав источников, оценки и текст не сравниваются |
| Обзор содержит содержательные разделы, включая методы, сравнение и сводную таблицу | check.py проверяет минимум семь заголовков и группы подстрок | Методы и сравнение объединены в одну группу; тела разделов и сводная таблица не проверяются |
| LaTeX собирается, итоговый PDF существует | В текущем наборе автоматических проверок нет | Требуется отдельная сборка в согласованной задаче |

Имена вроде bad_page или header_mismatch не являются машинными кодами ошибок
текущих скриптов: они выводят текстовые сообщения и код завершения 0/1.

## 4. Код и окружение

- Действующий код: checks/check.py, checks/test_properties.py,
  checks/check_graph.py, checks/verify_claims.py, scripts/run_verifier.py.
- Для локальных проверок использовать .venv/bin/python. В текущем сеансе
  подтверждён Python 3.14.4; это наблюдение, а не закреплённая версия среды.
- check.py, check_graph.py и verify_claims.py используют стандартную библиотеку;
  test_properties.py требует pytest. Фиксация зависимостей ещё не выполнена:
  requirements.txt отсутствует в базовом коммите. pyyaml и hypothesis
  текущими шестью тестами не используются.
- scripts/run_verifier.py вызывает python из PATH, а не sys.executable.
  Перед запуском необходимо убедиться, что PATH указывает на .venv.
- Для проверки без записи кэшей: python -B -m pytest checks -q -p no:cacheprovider.

## 5. Существующие тесты

В checks/test_properties.py существуют шесть тестов:

| Тест | Что устанавливает |
|---|---|
| test_every_category_has_row | Набор категорий равен четырём ожидаемым группам |
| test_every_source_file_exists | Путь source_file существует |
| test_indicator_names_reasonable | Название имеет допустимую длину или входит в список исключений |
| test_sensitivity_whitelist | Значение входит в существующий список, включая medium-high |
| test_indicator_unique | Названия не повторяются без учёта регистра |
| test_md_and_tex_literature_match | Число позиций литературы в Markdown и LaTeX одинаково |

Ранее перечисленные test_sensitivity_monotone, test_every_source_used,
test_row_count_matches_categories и test_source_page_integer_for_pdf
в текущем файле тестов отсутствуют. Их нельзя считать действующим контролем.

## 6. Последовательность запуска

| Шаг scripts/run_verifier.py | Команда | Что означает успех |
|---|---|---|
| dry | python checks/check.py | Реализованные ограничения заголовков и таблицы выполнены |
| smoke | python -m pytest checks/test_properties.py -q | Шесть существующих тестов прошли |
| sweep | python -m pytest checks -q | Прошли найденные pytest тесты; сейчас это тот же набор из шести |
| full | python checks/check_graph.py | Выполнены ограниченные проверки заметок и наличия провенанса |

Эти четыре запуска не образуют четыре независимых уровня научной проверки.
Время выполнения измерять при запуске; прежние оценки не гарантируются.
scripts/run_verifier.py перезаписывает results/verifier_log.csv. В этапе
документации запускать проверки отдельно, чтобы сохранить прежний журнал.
checks/ остаётся без изменений; фактические права доступа не выводятся
из наличия команды chmod в документации.

## 7. Содержательная проверка и приёмка

verify_claims.py создаёт бланк пяти утверждений с фиксированным seed=20261019.
Он распознаёт только некоторые ссылки с номером страницы, не открывает PDF
и не оценивает подтверждение тезисов. Отчёт за тот же день перезаписывается:
не запускать поверх существующего заполненного отчёта.

Для каждого тезиса проверяющий записывает файл, физическую страницу PDF,
дословную цитату, роль/имя проверяющего и итог. 2–3 тезиса сверяет человек,
остальные — агент с заданием «найди ошибку». Указать версию обзора, локальные
изменения, дату и seed. Минимум для приёмки обзора: подтверждено ≥ 4 из 5
и решение человека. Неподтверждённые и опровергнутые утверждения возвращаются
на исправление. Пять проверенных тезисов не доказывают весь обзор.

Для задачи по документации применяются её условия «Готово, когда»;
успешные технические проверки не означают новой приёмки научной статьи.
Агент оставляет status: выполнена; статус принята ставит только человек.

## 8. Бюджет и остановка

Действует AGENTS.md §7: максимум 20 вызовов инструментов на задачу,
контроль бюджета каждые пять вызовов. При недоступности token_budget()
сообщать количество шагов и отсутствие измеренного остатка. После двух
последовательных неудач check.py остановиться, записать причину в diary.md
и вернуться к согласованию объёма. Проверки не изменять ради успешного кода.

## 9. Журнал и исторические результаты

История находится в diary.md. results/verifier_log.csv хранит прежний прогон,
а results/caught_error_after.txt — прежний артефакт. Наличие упомянутого
в старой методике caught_error_before.txt не предполагать.

В записях от 2026-10-27 описаны внесённые ошибки source_page=abc для HWEC
и SOC content. Нецелое значение действительно отклоняет check.py;
упомянутый исторически test_source_page_integer_for_pdf сейчас отсутствует.
Новый прогон с переключением веток и внесением ошибки не выполнялся.

## 10. Известные отклонения и следующие этапы

- В таблице есть medium-high и нарушен нормативный порядок строк.
- Оценки SOC/clay, HWEC и агрегатной стабильности в отдельной таблице
  и таблице обзора расходятся; требуется отдельная сверка источников и условий.
- Прежняя привязка Cusset/Feeney и единиц PLFA в инструкции противоречива;
  документирование этой проблемы не заменяет чтения соответствующего PDF.
- Опубликованный spot_check_2026-10-27.md содержит незаполненные цитаты
  и итоги. Историческая ручная сверка трёх ссылок записана в diary.md;
  она не оформлена в этом отчёте как результат ≥ 4 из 5.
- PDF, изображения и извлечённые тексты исключены из Git. Перед воспроизведением
  проверить наличие нужных локальных материалов; их скачивание не разрешено.
- Новые проверки в src/, исправление научных оценок и изменение поиска —
  отдельные этапы. Согласование документации не означает их выполнения.
