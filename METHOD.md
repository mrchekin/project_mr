# Методика проверки: таблица индикаторов здоровья почвы

## 0. Паспорт

| Поле | Значение |
|---|---|
| Задача | Проверить таблицу индикаторов и связи графа до публикации обзора |
| Дисциплина | науки о Земле |
| Ветка верификатора | проверка данных (+ тесты на свойствах) |
| Дата записи методики | 2026-10-27 |
| Метка git | `exp-verifier` |

## 1. Замысел

- **Вопрос:** соответствует ли `paper/indicators_table.md` договору о схеме и согласован ли граф `notes/` с таблицей.
- **Гипотеза:** таблица полная (25 строк), у каждого индикатора есть заметка, у каждого источника — провенанс.
- **Что считается ответом:** код 0 от `scripts/run_verifier.py` (4 шага глубины).

## 2. Постановка

| Что | Значение |
|---|---|
| Что меняем | одна строка таблицы (индикатор) |
| Что фиксируем | столбцы, шкала sensitivity, набор категорий, формат source_page |
| Что измеряем | число нарушений договора (шт.), число строк (шт.), доля строк с валидным source_file (%) |
| Базовая линия | пустая таблица (0 строк) — все проверки красные; текущая — зелёные |

## 3. Данные

| Что | Значение |
|---|---|
| Источник | `paper/indicators_table.md`, PDF в `paper/` |
| Версия | коммит `<хэш>` (см. `git log -1 --format=%h -- paper/indicators_table.md`) |
| Лицензия | PDF — по лицензии издателя; таблица — собственная |
| Объём | 25 строк, 6 столбцов |
| Разбиение | не применимо (нет обучения) |

**Договор о схеме данных**

| Правило | Как проверяется | Код нарушения |
|---|---|---|
| Столбцы точно `indicator, category, method, sensitivity, source_file, source_page` | `checks/check.py::check_table` | `header_mismatch` |
| `category` ∈ {chemical, physical, biological, microbial, labile carbon} | там же | `bad_category` |
| `sensitivity` ∈ {low, medium, high, medium-high} | там же | `bad_sensitivity` |
| `indicator` уникален | там же | `duplicate_indicator` |
| `source_file` существует, расширение `.pdf/.md/.txt` | там же | `missing_source` |
| Для `.pdf` `source_page` — целое 1..999 | там же | `bad_page` |
| Нет заглушек (`test`, `todo`, `?`, `xxx`) | там же | `placeholder` |
| Строк ≥ 10 | там же | `too_few_rows` |
| Каждый `notes/Индикатор-*.md` соответствует строке таблицы (нет «сиротских» заметок) | `checks/check_graph.py` | `orphan_indicator_note` |
| Хотя бы 5 индикаторов таблицы имеют заметки (сейчас 5; цель — 25 к неделе 9) | там же | `few_indicator_notes` |
| У каждого источника есть `найденЗапросом` | там же | `no_provenance` |

**Известные нарушения:** нет.

## 4. Код и окружение

- Код: `checks/check.py`, `checks/check_graph.py`, `checks/test_properties.py`
- Команда: `python scripts/run_verifier.py`
- Окружение: Python 3.12, `requirements.txt` (pyyaml, pytest, hypothesis)
- Seed: не применимо (детерминированный расчёт)

## 5. Верификатор

- **Что проверяет:** договор о схеме таблицы (Д1–Д8), договор о графе (Д9–Д10), 5 свойств таблицы.
- **Команда:** `python scripts/run_verifier.py`
- **Где:** `checks/` (закрыт от записи, `chmod -R a-w checks`)
- **Чего не проверяет:** корректность научных утверждений (это `verify_claims.py` и человек), соответствие sensitivity реальной чувствительности из PDF, полноту обзора.  Полное покрытие заметками (5 из 25 индикаторов на 27.10.2026):остальные 20 индикаторов ещё не заведены в `notes/`.

| Свойство | Почему должно выполняться | Тест |
|---|---|---|
| Порядок sensitivity не возрастает (high → medium-high → medium → low) | Правило §5 `AGENTS.md` | `test_sensitivity_monotone` |
| В каждой категории ≥ 1 строка | Иначе категория пустая и обзор неполный | `test_every_category_has_row` |
| Каждый `source_file` существует | Иначе ссылка битая | `test_every_source_used` |
| Сумма по категориям = общее число строк | Нет «потерянных» строк | `test_row_count_matches_categories` |
| Длина `indicator` ≥ 2, кроме вайтлиста (`pH`, `EC`, …) | Отсекает заглушки, не ломая химию | `test_indicator_names_reasonable` |

## 6. Шаги глубины

| Шаг | Команда | Условие перехода | Время |
|---|---|---|---|
| dry | `python checks/check.py` | схема таблицы валидна | < 1 с |
| smoke | `python -m pytest checks/test_properties.py -q` | 5 свойств проходят | < 2 с |
| sweep | `python -m pytest checks -q` | все тесты проходят | < 3 с |
| full | `python checks/check_graph.py` | граф согласован | < 1 с |

## 7. Правило принятия (записано до запуска)

1. **Метрика:** число нарушений договора, шт. Целевое значение — 0.
2. **Повторы:** не применимо (детерминированный расчёт).
3. **Сравнение:** не применимо. Сравниваем с базовой линией — пустой таблицей (все проверки красные).
4. **Практический порог:** 0 нарушений. Любое нарушение — блокирует публикацию обзора.
5. **Выбор варианта:** не применимо (один вариант таблицы).
6. **Разбиение для вывода:** не применимо.
7. **Остановка:** две неудачи `scripts/run_verifier.py` подряд по одной причине — стоп, запись в `diary.md`, отчёт.

## 8. Бюджет

- Время счёта: < 5 с на полный прогон.
- Токены агента: не применимо (верификатор написан вручную).

## 10. Ограничения

- Верификатор проверяет **структуру и происхождение**, не научную корректность значений `sensitivity`.
- Соответствие `source_page` реальной странице в PDF проверяет `verify_claims.py` + человек (2–3 тезиса).
- Договор о графе проверяет только наличие заметок и провенанса, не их содержание.
- Если в `paper/` появятся новые PDF, не связанные с таблицей, проверка «каждый source_file существует» пройдёт, а «каждый PDF использован» — нет (это осознанно: PDF не по теме допустимы).
